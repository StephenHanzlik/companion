# Companion

A backcountry trip companion: **Plan** (prepare), **Ride** (record observations and
snow profile tests in the field), **Debrief** (summarize, reflect, submit). Personal
project, not affiliated with or endorsed by any avalanche education organization.

## Stack

- **Backend**: Go, `chi` router, `pgx`, `sqlc` for typed SQL (no ORM).
- **Database**: PostgreSQL. Structured tables for Trip/Plan/Observation/SnowProfileTest/
  Debrief, with JSONB columns where the shape is genuinely variable (snow test results,
  forecast payloads, checklists).
- **Frontend**: React + Vite + TypeScript, plain `fetch` against the REST API.
- **Local dev / test fixtures**: everything runs in Docker. Backend integration tests
  spin up a real, throwaway Postgres via `testcontainers-go` — no mocked DB layer.

## Requirements on this machine

Docker runtime is **Colima** (not Docker Desktop). Local toolchain (Go, Node, sqlc,
golang-migrate) is installed via Homebrew for fast native iteration; none of it is
strictly required — `make up` builds and runs everything inside Docker regardless.

```sh
colima start   # once per reboot / after `colima stop`
```

## Running it — two ways

**1. Full stack in Docker** (closest to how this would actually ship; no local
Go/Node/sqlc needed beyond Colima itself):

```sh
make up      # builds and starts postgres, migrate, seed, backend, frontend
```

- Backend: http://localhost:8080 (health check: `GET /healthz`)
- Frontend: http://localhost:5173
- Postgres: localhost:5432 (user/pass/db: `companion`/`companion`/`companion`)

```sh
make down    # stop and remove containers + the postgres volume
make test    # run backend integration tests in a container (spins up its own Postgres)
make sqlc    # regenerate internal/db/ from db/queries/*.sql + db/schema.sql, via Docker
```

**2. Native inner loop** (fast rebuilds/hot reload — Postgres stays in Docker,
backend/frontend run directly on the host):

```sh
make dev-db        # postgres + migrate + seed only, detached
make dev-sqlc       # regenerate internal/db/ locally (needs `sqlc` installed)
make dev-backend    # go run ./cmd/server against localhost:5432, with live recompiles
make dev-frontend   # npm run dev — Vite HMR
make dev-test       # go test ./... locally (still needs Colima running for testcontainers)
make dev-db-down    # tear down the dev Postgres
```

Run `dev-db` once, then `dev-backend` and `dev-frontend` in separate terminals.

There's no auth yet. A fixed-UUID demo user (`00000000-0000-0000-0000-000000000001`)
is seeded by `db/seed/seed.sql`, and the frontend hardcodes it as the owner/creator
of everything you create.

## Data model

```
User
Trip (owner, party, state, status: planning → active → debriefed)
 ├── Plan (1:1)            — objectives, route, forecasts, hazards, checklist, sign-off
 ├── Observation (1:many)  — timestamped field notes: weather/terrain/avalanche/red flag
 ├── SnowProfileTest (1:many) — CT/ECT/PST/pit profile; structured core + JSONB results
 └── Debrief (1:1)         — summary, decision reflections, lessons learned, submission
```

Full schema: `backend/db/schema.sql` (used by sqlc for codegen) and
`backend/db/migrate/0001_init.{up,down}.sql` (applied to real databases via
`golang-migrate`, run automatically by the `migrate` service in `docker-compose.yml`).
Keep these in sync as the schema evolves — see the comment at the top of `schema.sql`.

## Layout

```
backend/
  cmd/server/          entrypoint
  internal/config/      env-based config
  internal/httpapi/     chi router + handlers
  internal/db/          sqlc-generated (gitignored, regenerated by Docker build / `make sqlc`)
  db/schema.sql          current schema snapshot, sqlc's input
  db/migrate/            golang-migrate up/down files, source of truth for real DBs
  db/queries/             hand-written SQL, sqlc's input
  db/seed/                demo user seed
frontend/
  src/api/                fetch client + TS types mirroring the API
  src/pages/              TripsList, TripWorkspace (Plan/Ride/Debrief tabs)
docker-compose.yml         full local stack
Makefile                   up/down/build/sqlc/test/logs (Docker) + dev-* (native)
```

## Status / what's deliberately deferred

- No auth (single demo user).
- No offline-first sync for field capture — worth revisiting if this ever leaves
  the trailhead parking lot with no signal; that's a client-side sync-layer problem,
  not a backend one.
- No production frontend build/Dockerfile yet (dev-mode Vite server only) — add
  when this needs to actually be deployed somewhere.
- `go.sum` and `internal/db/` aren't committed; the backend Dockerfile regenerates
  both on every build (`go mod tidy` + `sqlc generate`). Once you've built at least
  once and have real toolchains available, feel free to commit `go.sum` for
  reproducibility.
